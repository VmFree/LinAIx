### 三、与 Agent 框架对接（切入）要点

#### 3.1 对接架构

```
┌─────────────────────────────────────────────────────────────────────────────────────────────────┐
│                                   Agent 框架对接架构                                            │
│                                                                                                 │
│  ┌─────────────────────────────────────────────────────────────────────────────────────────┐   │
│  │                              Agent 框架进程                                              │   │
│  │                                                                                         │   │
│  │  ┌─────────────────────────────────────────────────────────────────────────────────┐   │   │
│  │  │  框架原生功能                                                                     │   │   │
│  │  │  • 任务分解 (Task Decomposition)                                                 │   │   │
│  │  │  • Agent 角色定义 (Role/Persona)                                                │   │   │
│  │  │  • 工作流编排 (DAG/Graph)                                                       │   │   │
│  │  │  • 协作模式 (主从/流水线/投票)                                                  │   │   │
│  │  └─────────────────────────────────────────────────────────────────────────────────┘   │   │
│  │                                         │                                               │   │
│  │                                         ▼                                               │   │
│  │  ┌─────────────────────────────────────────────────────────────────────────────────┐   │   │
│  │  │                              LinAIx 适配器层                                     │   │   │
│  │  │                                                                                 │   │   │
│  │  │  1. 子任务检测  →  检测框架子任务创建 → 调用 TaskManager.create_subtask()         │   │   │
│  │  │  2. Skill 拦截  →  拦截框架工具调用 → 调用 SkillAPI.invoke()                    │   │   │
│  │  │  3. 模型拦截    →  拦截框架模型调用 → 附加 TaskId/SubTaskId → 调用 HAL           │   │   │
│  │  │  4. 结果适配    →  将 LinAIx 结果转换为框架原生格式                              │   │   │
│  │  │  5. 错误处理    →  将 LinAIx 错误转换为框架原生错误                              │   │   │
│  │  └─────────────────────────────────────────────────────────────────────────────────┘   │   │
│  │                                         │                                               │   │
│  └─────────────────────────────────────────────────────────────────────────────────────────┘   │
│                                              │                                                  │
│                                              ▼                                                  │
│                              LinAIx 内核 (通过 Framework 模块)                                  │
│                                                                                                 │
└─────────────────────────────────────────────────────────────────────────────────────────────────┘
```

#### 3.2 切入方式对照表

| 框架行为 | LinAIx 拦截点 | 使用的 LinAIx 模块 | 说明 |
|----------|---------------|-------------------|------|
| 框架创建子任务 | 适配器检测 | `task` | 适配器调用 `SubTaskManager::create_subtask()` |
| 框架调用工具 (Skill) | L4 Skill API | `skill`, `security`, `resource` | 拦截后经过权限/配额/审计链路 |
| 框架调用模型 (内部推理) | L1 HAL | `hal`, `resource` | 附加 TaskId/SubTaskId，执行配额检查 |
| 框架需要权限检查 | Security 模块 | `security/auth`, `security/authorization` | 统一权限验证 |
| 框架需要资源配额 | Resource 模块 | `resource/quota` | Token/显存/内存配额检查 |
| 框架需要审计日志 | Security/Audit | `security/audit` | 统一审计记录 |
| 框架需要可观测性 | Obs 模块 | `obs/metrics`, `obs/tracing` | 指标采集和链路追踪 |
| 框架间通信 | IPC 模块 | `ipc/channel`, `ipc/message` | Agent 间消息传递 |

#### 3.3 适配器接口清单

| 接口 | 职责 |
|------|------|
| `FrameworkAdapter::adapt_to_framework()` | 将 LinAIx Skill 包装为框架原生工具 (反向适配) |
| `FrameworkAdapter::adapt_to_linAIx_skill()` | 将框架工具调用转换为 LinAIx Skill 调用 (正向适配) |
| `FrameworkAdapter::intercept_model_call()` | 拦截框架模型调用，附加配额追踪信息 |
| `FrameworkAdapter::detect_and_report_subtask()` | 检测框架子任务创建，上报 TaskManager |
| `FrameworkAdapter::handle_quota_exceeded()` | 处理配额超限错误 |


### 四、各子系统详细说明

#### 4.1 Device HAL (`device/`)

| 项目 | 内容 |
|------|------|
| **核心定位** | 硬件资源读写抽象，屏蔽不同硬件 (GPU/NPU/CPU) 的差异 |
| **设计原则** | 最小接口 (仅读/写/分配/释放/控制) |
| **核心职责** | 设备信息查询 / 内存读写 / 内存分配释放 / 可选控制操作 |

